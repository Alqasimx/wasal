# تقرير Phase 1 — وصال

## الحالة الحالية

تم تنفيذ أساس Phase 1 ولوحة إدارة الأملاك التشغيلية، مع إبقاء التكامل التجاري الحقيقي مع WhatsApp وبيانات البنوك الفعلية مؤجلًا حسب قرار صاحب المشروع. لا يبدأ Phase 3 (الحجوزات) قبل اعتماد بوابة الإدارة ولوحة إدارة الأملاك.

## نطاق ما تم تنفيذه

### لوحات Filament

- لوحة Admin للإعدادات والمستخدمين والأدوار والصلاحيات وسجل التدقيق.
- لوحة Real Estate للبيانات العقارية وإدارة العقارات والإعلانات والطلبات.
- لوحة Property Management لتشغيل العقارات المُدارة.
- عرض اسم المستخدم والبريد في شريط سياق اللوحة.
- تنظيم التنقل في مجموعات: الأصول والإشغال، الإيجارات والتحصيل، الخدمات والصيانة، العمليات المتقدمة، الملاك والتسويات، والتقارير.

### إدارة الأملاك

- اتفاقيات إدارة العقارات مع المالك والمسؤول والرسوم والتجديد والتنبيهات.
- الوحدات والإشغال والعقود والمستأجرون.
- توليد الاستحقاقات الإيجارية وتحديث حالات المتأخرات.
- تسجيل الدفعات والدفعات الجزئية وإلغاء الدفعات مع التدقيق.
- الخدمات الدورية والموردون والفنيون وطلبات الصيانة.
- المعاينات والاستلام والمستندات والعدادات وقراءات الاستهلاك.
- المصروفات العقارية وتسويات الملاك من المسودة إلى الاعتماد ثم السداد.
- التقارير والتصدير بصيغة CSV.
- المهام المتكررة والتنبيهات الملونة حسب الأولوية والحالة.
- صفحة ملف عقار موحدة تجمع الإشغال، الاتفاقيات، الوحدات، الخدمات، الصيانة، المستندات، المصروفات، والمتأخرات.
- فتح المهمة والسجل الأصلي المرتبط من الإشعار عند توفر الرابط.

## الأتمتة والتنبيهات

توجد أوامر Laravel مجدولة في `routes/console.php`:

- `wasal:sync-rent-dues` يوميًا.
- `wasal:notify-due-rent-payments` يوميًا.
- `wasal:sync-property-service-schedules` كل ساعة.
- `wasal:sync-property-management-alerts` كل ساعة.
- `wasal:notify-due-tasks` كل دقيقة.

تعتمد إشعارات المهام على `due_at` و`notify_before_minutes` و`assigned_to_user_id`. تم إصلاح نطاق الاستحقاق ليتعامل مع قيمة التنبيه الفارغة كصفر، ومنع إنشاء إشعار مكرر لنفس المهمة، وحفظ وقت الفحص المستخدم في التشغيل.

في التطوير يجب تشغيل Scheduler في نافذة مستقلة:

```powershell
php artisan schedule:work
```

وفي الاستضافة التي لا تعمل فيها خدمة دائمة، يستدعى `schedule:run` من Cron كل دقيقة. عدم تشغيل Scheduler لا يعطل الواجهات، لكنه يوقف التوليد التلقائي للاستحقاقات والمهام والتنبيهات.

## قاعدة البيانات

أضيف ترحيل `2026_10_05_210000_add_priority_to_tasks_table.php` لإضافة أولوية المهام. يجب تطبيقه من PowerShell الذي يستخدم PHP 8.4 أو أحدث:

```powershell
cd C:\Projects\wasal
php artisan migrate
php artisan optimize:clear
```

## الاختبارات

توجد اختبارات Feature تغطي الصلاحيات، فصل اللوحات، الاتفاقيات، الإشغال، التحصيل، الصيانة، الخدمات الدورية، المعاينات، العدادات، التسويات، التقارير، والمهام والتنبيهات.

يجب تشغيلها بعد اختيار PHP الصحيح للمشروع:

```powershell
php -v
php artisan test
```

لا يسجل هذا التقرير ادعاء نجاح الاختبارات من جلسة تستخدم PHP 8.2؛ المشروع الحالي يحتاج PHP 8.4.1 أو أحدث حسب الاعتمادات المثبتة.

## ما هو مؤجل عمدًا

- مزود WhatsApp حقيقي وOTP تجاري؛ المستخدم الوهمي يبقى كما هو.
- تكاملات البنوك الحقيقية واعتماد بيانات البنك النهائية.
- لوحة المالك التشغيلية الكاملة.
- Phase 3 والحجوزات.

## الملاحظات المتبقية قبل اعتماد البوابة

1. تشغيل الترحيلات والاختبارات باستخدام PHP 8.4.
2. اختبار Scheduler يدويًا ثم تشغيله وفق بيئة التطوير أو Cron في الاستضافة.
3. اختبار الصلاحيات من حساب property_management والمحاسب والمعتمد المالي ومدير النظام.
4. اختبار رفع الملفات وتنزيلها وحدود أنواع وأحجام المرفقات.
5. مراجعة الروابط الداخلية والتصدير من المتصفح.
6. استكمال أي ملاحظات بصرية RTL تظهر أثناء اختبار المتصفح.

**الوضع الواقعي:** لوحة إدارة الأملاك قابلة للمراجعة التشغيلية، لكنها لا تُعلن جاهزة للإنتاج قبل تنفيذ اختبارات البيئة الفعلية أعلاه.
