# تقرير Phase 1 — وصال

**حالة التقرير:** محدث وفق الحالة الفعلية للمشروع  
**نطاق التقرير:** Phase 1 فقط  
**الوحدات المؤجلة:** العقارات، الحجوزات، إدارة الأملاك، الخدمات

## 1. الحالة العامة

تم تنفيذ أساس Phase 1 في المشروع، وتم إجراء الاختبار الشامل للمرحلة. المرحلة الحالية لا تهدف إلى إطلاق خدمات WhatsApp أو تشغيل عمليات مالية فعلية للشركة؛ هذه العناصر مؤجلة عمدًا إلى حين اكتمال التكوين التجاري والاشتراكات والبيانات اللازمة.

تُعد Phase 1 **منفذة ومختبرة ضمن نطاقها الحالي**، مع وجود عناصر تشغيلية وتجارية مؤجلة لا تمنع متابعة التطوير الداخلي.

## 2. نطاق Phase 1 المعتمد

يشمل نطاق المرحلة:

- أساس Laravel والتكوين العام.
- المستخدمون والملفات الأساسية للحساب.
- التسجيل وتسجيل الدخول واستعادة كلمة المرور.
- OTP مع مزود وهمي للتطوير والاختبار.
- الجلسات والأجهزة وSanctum API.
- الأدوار والصلاحيات RBAC.
- لوحة الإدارة عبر Filament.
- الدول والمحافظات والمدن والأحياء.
- العملات.
- البنوك كمرجع إداري مبدئي.
- إعدادات النظام.
- سجل التدقيق Audit Log.
- REST API تحت `/api/v1`.
- اختبارات Feature وUnit الخاصة بالأساس والمصادقة والصلاحيات والتدقيق.

## 3. ما تم تنفيذه

### الهوية والمصادقة

تم تنفيذ تدفقات التسجيل وتسجيل الدخول وتسجيل الخروج واستعادة كلمة المرور، مع دعم OTP عبر الواجهة المخصصة للمزود. المزود الحالي وهمي ومخصص للتطوير والاختبار، ولا يمثل تكامل WhatsApp إنتاجيًا.

تشمل البنية الحالية:

- `OtpService`.
- `AuthService`.
- `AuthController`.
- جداول OTP.
- جداول الجلسات والأجهزة.
- Sanctum للتوكنات.
- حماية كلمات المرور باستخدام hashing.

### RBAC ولوحة الإدارة

تم تنفيذ الأدوار والصلاحيات واستخدامها في حماية لوحة Filament ومواردها. تشمل لوحة الإدارة موارد المستخدمين والأدوار والصلاحيات والبيانات الجغرافية والعملات والبنوك والإعدادات وسجل التدقيق.

### البيانات المرجعية

تم تنفيذ التسلسل الجغرافي:

`Country → Governorate → City → District → Neighborhood`

كما تم تنفيذ العملات والبنوك والإعدادات الأساسية اللازمة للمرحلة.

### سجل التدقيق

تم تنفيذ Audit Log لتسجيل العمليات الإدارية الحساسة ضمن النطاق الحالي، مع حماية السجل من التعديل والحذف من خلال طبقة النموذج والموارد الإدارية.

## 4. الاختبارات والتحقق

تم إجراء الاختبار الشامل للمرحلة الأولى، ويغطي التدفقات الأساسية التالية:

- التسجيل.
- التحقق من OTP.
- تسجيل الدخول عبر OTP.
- تسجيل الدخول بكلمة المرور.
- تسجيل الخروج.
- استعادة كلمة المرور.
- انتهاء OTP ومحاولاته غير الصحيحة.
- تحديد معدل طلب OTP.
- الجلسات والأجهزة.
- حماية لوحة الإدارة.
- الأدوار والصلاحيات.
- سجل التدقيق.
- منع تعديل أو حذف Audit Log.
- عزل السجلات المالية حسب الصلاحية.
- خدمات المصادقة وOTP.

يُعتمد الاختبار الشامل كاختبار Phase 1 وفق نطاق التنفيذ الحالي. يجب عند كل تعديل لاحق إعادة تشغيل المجموعة الكاملة وتحديث هذا التقرير إذا تغيرت النتيجة.

## 5. العناصر المؤجلة عمدًا

### مزود WhatsApp الحقيقي

لم يتم الاشتراك في مزود WhatsApp حقيقي حتى الآن، ولذلك يبقى `FakeWhatsAppOtpProvider` هو المزود المعتمد للتطوير والاختبار.

هذا قرار مرحلي مقصود وليس عطلًا في Phase 1. عند الاشتراك مستقبلًا، يجب:

- إضافة بيانات المزود في إعدادات البيئة.
- تنفيذ المزود الحقيقي خلف الواجهة الحالية.
- إبقاء المزود الوهمي للاختبارات.
- اختبار الإرسال والفشل وإعادة المحاولة.
- منع كشف OTP في سجلات الإنتاج.

### بيانات البنوك واعتماد التعديلات

الشركة ما زالت قيد التكوين، ولم يتم إعداد بيانات الحسابات البنكية النهائية أو دورة اعتماد تعديل بيانات البنك. لذلك يقتصر وجود البنوك حاليًا على الأساس الإداري والهيكل القابل للتوسعة.

سيتم تنفيذ دورة الاعتماد عندما تتوفر:

- بيانات الشركة الرسمية.
- الحسابات البنكية المعتمدة.
- الشخص أو الدور المخول بالاعتماد.
- قواعد الفصل بين الإنشاء والتعديل والاعتماد.

### بيئة PHP والتبعيات

لا تُعد ترقية PHP أو تجهيز التبعيات جزءًا من إغلاق نطاق Phase 1 الوظيفي في هذا التقرير. تُسجل كمتطلب تشغيلي مستقل عند تجهيز بيئة التشغيل أو النشر، ولا تُعتبر سببًا لإعادة فتح نطاق المرحلة ما دام الاختبار الشامل للمرحلة قد تم واعتمدت نتائجه.

## 6. ما لم يبدأ بعد

لم يبدأ أي تنفيذ فعلي للوحدات التالية:

- العقارات.
- أنواع العقارات وخصائصها وإعلاناتها.
- الحجوزات والضيافة.
- الغرف والوحدات والباقات والتوفر.
- المدفوعات التشغيلية والعربون والاستردادات.
- إدارة الأملاك.
- العقود والإشغال والدفعات والمصروفات والصيانة.
- الخدمات والطلبات والمواعيد.

## 7. قرارات المرحلة

1. اعتماد المزود الوهمي للـOTP في التطوير والاختبار إلى حين الاشتراك في مزود حقيقي.
2. عدم اعتبار عدم وجود بيانات بنك نهائية عائقًا لتقدم التطوير الداخلي.
3. تأجيل دورة اعتماد بيانات البنك إلى ما بعد اكتمال بيانات الشركة والجهة المخولة.
4. عدم بدء العقارات أو الحجوزات أو إدارة الأملاك أو الخدمات ضمن Phase 1.
5. اعتبار الاختبار الشامل المنفذ مرجع تحقق للمرحلة، مع إعادة تشغيله بعد أي تغيير جوهري.
6. إبقاء ملفي الـMASTER مرجعًا للتخطيط والحالة:
   - `wasal_project_vision_plan_MASTER_2026-10-02.md`
   - `wasal_current_structure_state_MASTER_2026-10-02.md`

## 8. معايير إغلاق Phase 1

تُعتبر Phase 1 مغلقة ضمن نطاقها الحالي عند تحقق الآتي:

- وجود أساس المصادقة وOTP وRBAC ولوحة الإدارة والبيانات المرجعية وAudit.
- نجاح الاختبار الشامل للمرحلة.
- عدم بدء الوحدات المؤجلة قبل اعتماد نطاقها.
- توثيق العناصر التجارية المؤجلة بوضوح.
- الحفاظ على المزود الوهمي كخيار تطوير واختبار إلى حين تجهيز المزود الحقيقي.

## 9. المرحلة التالية

بعد اعتماد هذا التقرير، يبدأ العمل على **Phase 2 — العقارات** وفق نطاق مستقل وخطة تفصيلية، مع الحفاظ على أساس Phase 1 وعدم إعادة فتح العناصر المؤجلة تجاريًا إلا عند توفر متطلباتها.

تبدأ Phase 2 بتحديد الشريحة الأولى من العقارات، ثم تنفيذ أنواع العقارات والخصائص والإعلانات ودورة المراجعة والنشر، مع الالتزام بإخفاء بيانات المالك والموقع الدقيق عن الجمهور وتسجيل العمليات الحساسة في Audit Log.
